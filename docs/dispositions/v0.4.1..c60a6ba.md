## Pattern

Causes 1 and 3 share one shape: **a module took ownership of a behaviour and did not enumerate every
instance of it.** `module_symbols` enumerated the ways a file resists being read and stopped one
short of decoding. `load` enumerated the ways a marker can be malformed for `schema` and did not ask
the same of `evidence:`. `AGENTS.md` states this rule under Script And Dependency Policy, with
`skill_model.NAME_PATTERN` as the worked example, and both of these are the failure it describes —
not a copy left outside a new owner, but a case left out of an enumeration the owner already had.

The pattern-level repair is the one the rule already prescribes and neither of these got: when a
function answers a question about a class of inputs, list the class. Nothing checks it; what makes it
re-runnable here is that each repair's guard names a state and a test, so the enumeration is visible
as rows rather than as an intention.

Cause 2 is a different and sharper shape: **the note above the code stated the rule correctly and
the code measured something else.** The comment said the word's closer is where the quote *next*
appears; the expression asked whether it appears at all. Nothing in this repository would have caught
that — a comment is not a claim any check reads — and the pre-existing test passed under the defect,
which is the measurement recorded in `docs/guards.md`.
