## Pattern

Causes 1 and 2 share one shape, and it is the shape the project memory of this range already names:
**a rule established in a round is not applied to that round's own new output.** Cause 1 is a
self-check that verifies placement for the ids it placed. Cause 2 is a ledger clause obeyed toward
the input and not toward the turn obeying it. In both, the mechanism is turned outward — at the prior
record, at the prior round's findings — and the round's own product is the one thing it does not
examine.

The pattern-level repair is not a further clause. Both self-checks already exist and both passed; a
third statement of them would pass the same way. What separates a self-check that catches this from
one that does not is **whose list it answers from**: a check answering from what the record contains
can only confirm what is there, while a check answering from an external list — the prior record's
open dispositions, this round's own accepted findings — can report an absence. Repair 1a states the
self-check that way, and 2a is the same move applied to the ledger.

This is the fourth consecutive round whose every finding is in the record apparatus rather than in
the product. The previous record said the apparatus now costs more findings per round than the thing
it governs. Nothing in this round contradicts that; it is a standing observation for
`development-knowns.yaml`, and this record does not write one.
