## Pattern

Three of the six findings are in the guards ledger, and that is the shape worth stating: **the file
built so a later round would not have to trust prose became prose a later round could not trust.**
One row quoted numbers from a record that says something else, one promised a red that does not
happen, and one could not be read without the row above it.

The claim that failed is the one that matters, because of *how* it failed. The revert I ran did
apply — I checked that, after an earlier probe in this range reported no failures with an edit that
had not landed. What I did not check is that the edit was the code that had been there: it read
`Path("scripts")` against the working directory rather than the fixture's root, so it consulted this
repository's own tree and reddened cases for a reason the repair had nothing to do with. **Confirming
that an edit landed is not confirming that it is the pre-repair code**, and the second is what a
revert probe means.

Cause 2 is the same shape as the previous round's cause 4, one layer in: a discipline the type states
and a field added beside it. That the field is unread today is not the argument the review makes, and
it is right — `read_whole.Whole`'s own docstring records that a convention held by care was what the
earlier rounds already had.
